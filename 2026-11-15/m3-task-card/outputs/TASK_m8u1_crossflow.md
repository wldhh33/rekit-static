## 1. R76：暂态写的可判定定义

### 1.1 定义（写进代码常量 `_TRANSIENT_RULE`，先于实现被读到）

> 设指令 w（地址 a）写寄存器 r，目标点 t > a。w 对 (r, t) 是**暂态写**，当且仅当存在
> b（a < b ≤ t）使
> **(T1)** b 是同一函数内**已解出**的指令，且把 r 写成 a 之前 r 的值（可判定的复原证据）；
> **(T2)** (a, b) 内没有对 r 的其它写；
> **(T3)** (b, t) 内没有对 r 的写。
>
> 本轮可判定的复原证据集合为**空**：没有任何「抵消配对」被承认为证据。

判据落在 [callfacts.py](file:///d:/数据/下载/逆向学习工作体系_2026-11-15/2026-11-15/m3-task-card/work/rekit/callfacts.py#L71-L88)。
实现处 [§`_operand_facts`](file:///d:/数据/下载/逆向学习工作体系_2026-11-15/2026-11-15/m3-task-card/work/rekit/callfacts.py#L231-L262)
只问一件事：栈槽定义之后、调用点之前，基址寄存器有没有被**持久**写；有 ⇒ 槽 abstain。
`call` 在这里没有任何特殊分支，它只是"某条写了 rsp 的指令"。

### 1.2 为什么本轮「可判定复原证据集合」是空的

`call` 确实写 rsp（压返回地址）。要让 T1 成立，需要一个**已解出的**指令 b 把 rsp 复原：

- `ret` 在被调函数体内，不在本函数已解出的窗口内 ⇒ 本层无法把它当证据；
- `ret imm16` 会额外弹出参数（callee-cleanup），净效果是 `+8+imm16` 还是 `+8` 取决于
  调用约定 ⇒ 即使能看到被调方，也不能说"复原到进入时的值"；
- 认定调用约定属于 ABI 推断，本层明令禁止（与 M6-U2 的 abstain 口径一致）。

因此 T1 对 `call` 不成立。`call` 的 rsp 写按持久写处理——这是判据的**应用结果**，
与 `mov rsp, rbp` 走同一条判定路径，代码里没有 `if fam == "call"` 的豁免。

### 1.3 这个定义怎么被反例证伪

常量的 `falsify` 字段（[同处](file:///d:/数据/下载/逆向学习工作体系_2026-11-15/2026-11-15/m3-task-card/work/rekit/callfacts.py#L83-L88)）写了两向：

- **证伪「持久写」**：给出一个被报出的 rsp 基址槽事实，其窗口内 call 的被调方在返回时
  rsp 与进入时不等（如 `ret 8` 的被调方、或在被调方里 `pop` 掉返回地址后尾跳）。
  该槽在调用点的地址就与定义点不同，事实即错。
- **证伪「暂态写」**：把 call 判成暂态后，任何 callee-cleanup 的被调方都能立刻造出上面这个
  反例——这正是本轮选「持久写」的理由。

可判定地执行：`verify_callfacts.py --selftest` 的 **R76 正例**（[日志](file:///d:/数据/下载/逆向学习工作体系_2026-11-15/2026-11-15/m3-task-card/work/evidence_m8u1_scripts.log)）：

```
[selftest] R76 正例 0x1077 窗口内含 call 0x1061，伪造 [rsp-0x8] 槽事实→ 已检出（call 的 rsp 写按持久写）
```

即：只要实现回到「call 不写 rsp」的老口径，这条注入立刻 FAIL。判据不是空转的文字。

### 1.4 实测：431 条事实转为弃权，一条也不少

| 样本 | 槽事实（前→后） | 槽弃权（前→后） | 其中 `why=call` | 窗口截断 |
|---|---|---|---|---|
| cli-64.exe | 96 → **73** | 14 → **37** | 23 | 3 → 3 |
| bin_ls.elf | 378 → **350** | 14 → **42** | 28 | 51 → 51 |
| dyn_static | 2951 → **2571** | 82 → **462** | 380 | 164 → 164 |

每条新增弃权都指名了触发它的 call 地址，例如 cli-64 `0x1340` 站点的 `[rsp+96]`：

```
窗口内 0x1313 是 call：它写 rsp（压返回地址），复原依赖被调方的 ret 与调用约定
（ret imm16 会多弹参数），本工具不推断调用约定 → 该槽在调用点的地址不可判；

```

单测锚点：`test_r76_call_write_to_rsp_is_persistent_not_exempt`（站点 0x1340 / `slot:[rsp+96]`
/ call 在 0x1313 / "栈平衡契约"）与 `test_r76_rule_is_documented_with_falsification`。

### 1.5 独立侧同步（不是"让独立侧闭嘴"）

`verify_callfacts._writes` 现在对 `call/lcall` 返回 `{"rsp"}`，`_NO_DEST_XFER` 只剩
`{"jmp","ljmp"}`。也就是说独立判据也认为 call 写 rsp——两边在同一条事实上达成一致，
分歧只在"是否持久"，而那由 §1.2 的判据回答。**没有**靠改独立侧把数字做小。

### 1.6 对 M8-U0 的更正

M8-U0 §1.3 第 2 条写「`call` 压返回地址→返回即复原，对窗口内栈槽基址是否仍有效无持久影响」，
并把 §1.4 的 23/28/380 条（合计 431）归因为「独立侧口径错」。本轮结论：

- 独立侧**没有**错判事实：rsp 在 call 处确实变了；
- 错的是实现侧**报出**了这些槽事实——它们应当在实现侧 abstain；
- 因此正确的修法是实现侧按 R76 收紧（§1.4），而**不是**把 call 从写集合里抹掉。

M8-U0 §1.4 的 431 条归因，以本节为准。

## 2. 跨块：只沿确定边，失败必须写缺什么

### 2.1 边与索引

[`_cross_index`](file:///d:/数据/下载/逆向学习工作体系_2026-11-15/2026-11-15/m3-task-card/work/rekit/callfacts.py#L348-L378) 只从
`res["cfg"]["edges"]["definite"]` 建前驱表。另外四类（`speculative` / `cross_function` /
`undecoded` / `unresolved`）**不进前驱表**，而是进 `nondet_in`：它们不在回溯路径上，
但它们的**存在**会让「这块的入边已完整」这个前提不成立，所以一旦命中就 abstain。

不为了让覆盖率好看把疑似边当确定边：这条是硬编码的——`preds` 只有 definite 一个来源，
没有"如果没有确定前驱就用疑似边补"的兜底。

### 2.2 回溯算法

[`_cross_before`](file:///d:/数据/下载/逆向学习工作体系_2026-11-15/2026-11-15/m3-task-card/work/rekit/callfacts.py#L530-L537)：

1. 先在调用点所在块内倒扫（`_scan_block`），遇到屏障（无法解码/未建模隐式读写）就截断；
2. 块内没有该操作数的写 ⇒ 递归到所有**确定**前驱（`_cross_exit`/`_cross_merge`）；
3. 合流点要求**所有**确定前驱给出**同一个**定义地址，否则 `disagree`；
4. 回边用**回溯栈**（`key=(operand, 块首)`）检测，命中即 `loop`；
5. 深度上限 64 块、分支上限 32 条，超限即 `depth`/`breadth`（写清是哪个上限）。

结论放进 `sites[i]["cross_facts"]`，与同块 `facts` **分开存放、分开计数**，不混进
`facts`（单测 `test_cross_block_facts_stay_out_of_same_block_list`、verify 的 G 段都查这一点）。
每条事实带 `branches`：从调用点所在块到定义块的**线性**块链（合流处每支各一条），
供外部逐跳复核；分支不是拼成一串的"路径集合"。

### 2.3 「写缺什么」不是一句"不可判定"

`_cross_merge` 失败时把**根因**逐层传上来（嵌套的 `ambiguous` 只带自身 `why` 会把最深处
的 loop/nondet/entry 丢掉），再由 `_cross_missing` 翻译：

| 状态 | 缺什么（文案要点） |
|---|---|
| `entry` | 回溯到函数入口/无确定前驱：缺调用方在该入口前对该寄存器的赋值 |
| `nondet` | 块 X 有非确定入边（`speculative`/`cross_function`/…）：缺这些入边的目标判定；含 `unresolved+jmp_ind/call_ind` 时点名「跳转表/函数指针，目标不可静态确定」 |
| `loop` | 回溯遇到回边（循环）：缺不动点迭代/循环不变式，环上可能有多次定义 |
| `disagree` | 合流处给出不同定义（列出各地址）：缺「各路径同一定义」 |
| `barrier` | 0x… 指令无法给出读写事实（原因）：缺该指令语义，不能越过它声称「块内无写」 |
| `depth` / `breadth` | 超过 64 块 / 32 支：缺更长的路径 / 路径剪枝判据 |
| 栈槽 | 跨块只追寄存器：栈槽需要跨块栈指针值追踪（缺） |
| 同块窗口截断 | 窗口在 0x… 截断：缺该指令语义，不能越过它回溯 |

单测 `test_cross_block_loop_abstains_and_names_the_cycle` 用 dyn_static 的真实回边
（如块 `0x4011ba`）走同一条 `_cross_merge` 路径，断言文案含「回边」「不动点」——
根因传播要是丢了，这条会失败。

### 2.4 实测：跨块弃权按原因分列

（按**首要原因**归类；一条弃权可能同时点名多个原因，例如 dyn 有 2 条同时含
「回边」与「非确定入边 cross_function」，且非确定入边共出现在 3 条文案里。）

| 原因 | bin_ls.elf | dyn_static |
|---|---|---|
| 回边/循环（缺不动点迭代） | 13 | 20 |
| 合流处定义不同（含嵌套） | 3 | 21 |
| 非确定入边（本轮命中的是 `cross_function`） | 0 | 1 |
| 回溯到函数入口（缺调用方赋值） | 0 | 1 |
| 屏障（块内无法解码/未建模，含嵌套） | 1 | 5 |
| 栈槽（跨块只追寄存器） | 2 | 26 |
| 同块窗口在屏障处截断 | 3 | 1 |
| **合计** | **22** | **75** |

`cli-64.exe` 三项全 0。原因不是"跨块没跑"，而是**没有可追的操作数**：
cli-64 的 153 个调用点里，98 个是 `call rel32`（无操作数），55 个是 `call [rip+disp]`
（IAT 跳板）；rip 相对寻址既不是基址/索引寄存器，也不构成 `[rsp/rbp±d]` 栈槽，
所以 `_effects` 对它给出**空读集合**（[callgraph.py](file:///d:/数据/下载/逆向学习工作体系_2026-11-15/2026-11-15/m3-task-card/work/rekit/callgraph.py#L390-L391)
只取 `indirect` 操作数；[`_slot_name`](file:///d:/数据/下载/逆向学习工作体系_2026-11-15/2026-11-15/m3-task-card/work/rekit/callgraph.py#L313-L321)
对 `rip`/带索引的内存拒绝）。探针实测：cli-64 `无读操作数 153 / reg 读 0 / slot 读 0`。

对照：bin_ls `reg 读 35 + slot 读 2`，dyn_static `reg 读 156 + slot 读 26`；去重后
分别对应 31 / 153 个待判操作数（9+22、78+75）。

## 3. 期望值来源：外部工具 + 手工算术

### 3.1 外部工具 objdump（G 段，`verify_callfacts.py`）

`_cross_scan` 用 `objdump -d -M intel --no-show-raw-insn` 的文本做五件事，全程不 import
`callfacts` 的判定函数（`callfacts` 只作为**被测输出**读取）：

1. **定义指令真写该操作数**（`_written`，本文件内的独立写集合模型）：声称在 0x… 定义了 r，
   objdump 文本里那条指令必须真的写 r，否则 FAIL；
2. **块内其后无再写**：定义点到调用点之间，同块内不得有第二条写 r 的指令（"最后一次"成立）；
3. **逐跳后继复核**（`_objdump_edges`）：跨块分支是上游序列，`br[i] → br[i-1]` 必须是
   objdump 文本里的真实后继（跳转目标减 delta 归一），**不看** recdesc 的边类别；
4. **前驱完整性反推**：用 objdump 后继反推集合，要求实现给出的分支起点集合与该集合一致；
5. **账目对平**：跨块事实/弃权/站点数可由 sites 重算；跨块事实不得与同块事实重复、
   不得与调用点同块。

实测（`evidence_m8u1_scripts.log`）：

```
跨块（只走确定边）: 事实 9 ｜ 弃权 22 ｜ 站点 30 ｜ 分支 11 ｜ 逐跳复核 45 ｜ 定义指令经 objdump 确认 9 ｜ 未建模 0 ｜ 前驱不完整 0
跨块（只走确定边）: 事实 78 ｜ 弃权 75 ｜ 站点 124 ｜ 分支 139 ｜ 逐跳复核 216 ｜ 定义指令经 objdump 确认 78 ｜ 未建模 0 ｜ 前驱不完整 0
```

**它证不了什么**（诚实边界）：objdump 只能证明"给出的路径每跳都是真边、定义指令真写该寄存器"，
不能证明"别的路径上没有别的定义"——后者依赖前驱完整性（第 4 项）与 definite 边的质量。
未建模助记符单列（本轮 0），不让"模型没覆盖"混成"检查通过"。

### 3.2 手工算术：3 个案例逐条读数

`evidence_m8u1_numbers.log` 末尾直接贴 objdump 文本，人工读出"最后一次写"：

**① bin_ls.elf `0x48f6` 读 rax，rax 最后一次写 `0x48ea`（跨块）**

```
48e5: call 48aa
48ea: mov  rax,QWORD PTR [rip+0x23b17]   ← 定义（块 0x48cf 内）
48f1: test rax,rax
48f4: je   48fa
48f6: call rax                            ← 使用
```

调用点所在块 `0x48f6` 的确定前驱链 `0x48f6→0x48cf`，定义在 `0x48ea`：手算一致。

**② dyn_static `0x404b4f` 读 rdx，rdx 最后一次写 `0x404b46`（跨块）**

```
404b44: jne 404b20
404b46: mov rdx,QWORD PTR [rbp+0x0]   ← 定义（块 0x404b46 内）
404b4a: test rdx,rdx
404b4d: je  404b20                     ← 块终结符
404b4f: call rdx                       ← 使用（块 0x404b4f）
```

块链 `0x404b4f→0x404b46`，且 `0x404b46` 是本块块首：手算一致。

**③ dyn_static `0x4517a0` 读 rbp（合流/回边案例）**

```
45177a: mov rbp,QWORD PTR [rbx+0xd8]   ← 定义
45178b: sub rax,rdx
45178e: cmp rax,0x92f
451794: ja  451898                     ← 另一条确定前驱所在块
451798: (落空)
45179a: mov rsi,rsp
45179d: mov rdi,rbx
4517a0: call QWORD PTR [rbp+0x90]      ← 使用（块 0x45179a）
```

块链两条：`0x45179a→0x45177a`（直落）与 `0x45179a→0x451898→0x45177a`（`ja` 出去的块
跳回 `0x45177a`）。两条都落在 `0x45177a` 同一条 `mov` 上，合流处同址：手算一致。

这三例都是**手工算术 + 外部反汇编文本**，没有一处来自 `callfacts` 的自报输出。

## 7. 边界（本轮不做的）

- **after（使用侧）跨块不追**：缺「沿确定后继路径的首次使用」判定，宁可不报；
- **跨块不追栈槽**：需要跨块栈指针值追踪，本轮一律 abstain（bin_ls 2、dyn 26）；
- **合流要求"同一定义地址"** 是刻意保守：同一值经不同寄存器转手也会被 abstain；
- **跳转表/间接目标**：命中 `unresolved` 入边时 abstain 并点名；本轮的三个样本上
  没有 `unresolved` 类入边（非确定入边只出现 `speculative` 15 条 / `cross_function` 339 条），
  所以"跳转表"文案在本轮实测中未触发，仅由代码路径与单测覆盖；
- **深度/分支上限**（64 块 / 32 支）未在实测触发，超限会 abstain 而不是截断成"无定义"。

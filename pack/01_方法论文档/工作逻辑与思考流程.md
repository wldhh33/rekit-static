# 工作逻辑与思考流程（AI 助手逆向自我训练方法论 v1.0）

> 这份文档把"AI 助手每天 10:33 自动执行逆向自我训练"的完整思考流程整理出来。
> 适用于：想复刻这套自我训练闭环的人或 Agent。核心思想一句话——
> **把"学习"变成"可验收的工程任务"，把每天的失败变成规则库里的防坑条款。**

---

## 一、总循环：五步闭环（每日执行，缺一不可）

```
┌─ 1. 定位 ──────── 读路线图 + 项目进度档案 → 确认今天学什么、做什么
├─ 2. 巡检 ──────── 多源搜索社区动态（信息源矩阵），筛 5-8 条带来源摘要
├─ 3. 知识点 ────── 按当前阶段主题讲一个核心概念：原理 + 本机实证 + 练习建议
├─ 4. 实操验收 ──── 先写验收标准（可证伪）→ 真实执行 → 逐条判定 → 证据落盘
├─ 5. 归档输出 ──── 规则沉淀 + 进度回写 + 日报 docx
└─ 反馈回路 ─────── 昨天的返工决定今天的任务强度（降档条款）
```

**关键认知：巡检不是看新闻**。每条动态都要回答"对我的项目/知识体系有什么用"，
与当日主题共振的条目会直接变成实操任务的灵感（如 IDA 出官方 MCP → 我做 rekit MCP）。

## 二、实操任务的铁律：标准先行

布置任务时**先写验收标准，再动手**，且标准必须：
1. **可量化**：数字说话（"11 字段全等"、"35/35"、"58→73 断言"），拒绝"基本完成"
2. **可证伪**：每条标准对应一个"如果做错了会被抓住"的检查动作
3. **交叉验证优先**：自己的输出永远不是标准，权威工具输出才是——
   ELF 用 readelf/objdump，PE 用 pefile/objdump，格式争议用字节级 dump 一锤定音
4. **不许事后放宽**：标准写定了就不能为了过关而降低；发现问题只能走变更日志（如实记录）
5. **负样本必测**：正样本对不算对，"错误输入优雅降级"才是工程质量
   （不存在的文件、魔数对但截断、构造的陷阱样本）

## 三、三层错误防御体系

**第 1 层：写代码前**（预防）
- R1 字段计数先行：struct 串先列字段表数个数
- R2 地址表先画：RVA→RAW 区间表检查无重叠再写构造器
- R17 样本布局先行：三态判定先画"状态×样本"覆盖矩阵

**第 2 层：验证时**（抓错）
- R3 三方交叉验证是金标准：构造器 / 解析器 / 权威工具互相独立，
  专门抓"自以为对"的 bug（历史战绩：抓出过数据目录错位、布局重叠两个隐藏 bug）
- R4 验收失败先怀疑验收器：历史上返工 Top1 是验收脚本自身错位，不是被测代码
- R25–R27 验证脚本三板斧：锚点唯一性检查 / 正则边界对齐列语义 / 列宽差异用 \s+

**第 3 层：沉淀时**（防再犯）
- 每个坑当天变成 R 编号规则（见规则库），写代码前必读
- 规则不是收藏夹——11-14 降档日把 R25 做成代码里的前置断言，规则变成防御工事

## 四、速度基线与降档条款（自我惩罚机制）

- 双基线实测定标：扩展型任务 1–2 分钟，从零型 5–8 分钟（首次实测得出，非拍脑袋）
- **当日返工 ≥3 次 → 次日该模块任务降档为巩固型**，且必须"从轻 + 针对性加固"
- 降档不是躺平：11-13 验证脚本 3 返工 → 11-14 只做收口不加功能 + 把 R25 做成前置
  断言 → 双 0 返工，条款第一次完整闭环
- 所有失败如实记录在进度档案，**严禁虚报**——失败本身就是最有价值的基线数据
  （基线 B 的 8 次返工明细是整个项目最贵的资产）

## 五、中断应对（长任务执行纪律）

- 长任务按轮数上限设计：**每个阶段完成立即落盘**（文件 > 对话记忆）
- 中断点不可控，恢复时先验"文件是否真的写下去"（写文件被中断 = 文件不存在）
- **交付优先于收尾**：宁可中断在排版，不可中断在核心执行
- 恢复流程：汇报已完成成果 + 剩余步骤精确到"第几步"，用户一句"继续"即从断点续跑

## 六、长期项目管理（借鉴 craft-anything）

- **章程先行**：CHARTER 写清价值声明/里程碑/完成标准/变更规则
- **里程碑不可跳**：M1 → M1.5 → M2 → ...，跳过 = 标准降级 = 违反变更红线
- **超额项回写**：做了超出章程的事，要更新章程并记变更日志（章程与现实对齐）
- **每个任务的断言必须入库常绿**：一次性验收只证明当天，常绿套件才能证明持续
- **双身份设计**：CLI（人用）+ MCP（Agent 用），工具养工具的飞轮

## 七、知识点的讲法（费曼式自证）

每个知识点必须包含：原理 → 本机实证（没有环境就设计替代实证）→ 练习建议。
实证示例：讲 ASLR 就连跑两次 ldd 看基址变化；讲 PIE 断点就用自家工具拿静态 RVA 配合。
**讲不清楚 = 没学会**，写出来的知识卡就是理解的自证。

## 八、成果归档惯例

```
learning/artifacts/YYYY-MM-DD/
├── TASK_*.md            # 先行的验收标准（执行前写定）
├── verify_*.py          # 验证脚本（可复用模板）
├── evidence_*.log       # 执行证据（含失败与返工记录）
├── *_knowledge_and_rules.md  # 知识卡 + 当日新规则
每日项目/YYYY-MM-DD/      # 对外交付：日报 docx + 学习归档副本
每日项目/rekit长期项目/    # 项目快照
```

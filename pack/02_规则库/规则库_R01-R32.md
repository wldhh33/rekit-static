# rekit 规则库 R01–R32（全量合集）

> 十天真实执行沉淀的 32 条防坑规则。编号即时间序，每条都对应至少一次真实返工或实证。
> 使用方式：写代码前通读一遍；踩新坑时追加新编号，永不删除旧条目。

## 第一阶段：基线期（R1–R5，2026-11-07）

- **R1 字段计数先行**：连续同类型字段多的 struct 串，先列字段表数个数再写串
  （CheckSum 在 3 处漏了 3 次的血泪）
- **R2 构造器先画 RVA→RAW 地址表**：检查区间不重叠再写字节
- **R3 三方交叉验证是金标准**：构造器 / 解析器 / objdump 互相独立，专门抓"自以为对"的 bug
- **R4 验收失败先怀疑验收器**：验收脚本自身的正则错位是历史返工 Top1
- **R5 PE32 与 PE32+ 差异清单**：ImageBase 4/8B、栈堆 4/8B×4、BaseOfData 仅 PE32、DataDirs 起点 96/112

## ELF 动态段期（R6–R7，2026-11-07）

- **R6 vaddr ≠ file offset**：ELF 动态段的地址值是虚拟地址，必须经 PT_LOAD 映射换算
  `off = vaddr − p_vaddr + p_offset`；直用会越界（有反证实验）
- **R7 glibc 2.34+ 无独立 libm 依赖**：libm 已并入 libc，别拿 libm 当"多依赖"测试样本

## 符号表期（R8–R12，2026-11-08）

- **R8 st_value 是 vaddr**：链接视图虚拟地址，与 readelf -sW 显示值一致即自证
- **R9 sh_link 是节索引**：符号表的配套字符串表靠它找（.strtab/.dynstr）
- **R10 readelf 符号名 @VERSION 陷阱**：readelf 显示 `getenv@GLIBC_2.2.5`，比对时要剥版本后缀
- **R11 SHN_UNDEF 语义**：st_shndx==0 = 导入符号，运行时由动态链接器解析，value 为 0 属正常
- **R12 验收脚本正则错位是历史返工 Top1**：多次复现，催生 R13 升级版

## 重定位期（R13–R15，2026-11-09）

- **R13 正则分组三连坑（R12 升级版）**：多分组正则必须先写分组清单注释
  （1=offset 2=info 3=type...）；改正则必全文搜索 m.group( 同步引用
- **R14 验收脚本防空转**：filter 驱动的检查必须带计数下限（0 匹配时必须报错而非静默通过）
- **R15 权威工具显示怪癖清单**：readelf/objdump 各有显示怪癖（伪符号 *ABS* 等），对拍前先建清单

## checksec 期（R16–R18，2026-11-10）

- **R16 常量表必须经权威源校验后才可用于语义判定**：DT_TAGS 显示名有 3 处错位史
  （潜伏两日，语义依赖时爆雷）——常量表与权威输出逐项对拍才算数
- **R17 语义型任务的样本布局先行**：三态判定类任务先画"状态×样本"覆盖矩阵再动手，缺格先补样本
- **R18 工具写入权限分层**：Bash 与 Write/Edit 工具的权限通道不同，root 属主文件写入会被拒——
  遇 Permission denied 先查属主再换通道

## 调用约定/SIMD 期（R19–R21，2026-11-11）

- **R19 内联吞噬调用链**：-O2 下小函数默认内联，call 从调用方消失——
  想看 call 必须加 noinline/volatile；指令≠源码一一对应
- **R20 栈参数右→左**：push 序 = 参数序的逆序；帧内定位锚 rbp 而非 rsp
  （被调方可能 and rsp 重对齐，rsp 锚会失真）
- **R21 传参双轨**：整型与浮点寄存器编号独立计数（rdi..r9 与 xmm0..xmm7 互不占位）

## Rich 头期（R22–R24，2026-11-12）

- **R22 权威工具输出须源码级对齐**：不读权威库源码就按直觉解释其输出格式，会造出
  "看起来像 Rich^key"的误读（真实案例：把真实第 11 对当成了尾部标记）
- **R23 双向锚定防御巧合字节串**：找签名时若存在"明文锚 A + 由 A 派生的加密锚 B"，
  必须双锚验证——单向锚会被大文件深处的巧合字节串命中（pefile 就栽在这，rekit 比它严）
- **R24 格式话术统一律**：同一结构在"存储域/明文域"两种描述下形似实异（DanS^ck,ck,ck,ck
  vs DanS,0,0,0），对拍前先声明站在哪个域

## 导出表期（R25–R27，2026-11-13）

- **R25 锚点唯一性检查**：split 外部工具输出前先确认锚点串只出现一次
  （"Export Address Table" 在 objdump 输出出现 3 次——split()[1] 静默取错段）
- **R26 正则边界对齐列语义**：(\w+) 会把行尾 Type 列 "Export RVA" 吃成函数名——
  捕获组必须锚定到列的确切语义
- **R27 列宽差异用 \s+**：4 位 hint 与 8 位 RVA 的填充空格数不同，对齐列一律 \s+

## 收口期（R28–R29，2026-11-14）

- **R28 分诊工具崩溃路径可控律**：对外 CLI 的失败路径语义分层且零 traceback
  （exit 2 分诊失败 / exit 3 解析失败），负样本三件套必测
- **R29 模板函数参数化保输出一致律**：统一入口复用模块渲染时参数化 main(argv=None)，
  输出一致是构造性保证，diff 同时证明路由正确

## MCP 期（R30–R32，2026-11-15）

- **R30 协议服务器双错误语义**：工具级错误 → isError:true 连接存活；协议级错误 →
  JSON-RPC error；stdout 是协议通道（flush 必须）、日志只走 stderr
- **R31 权威期望提取防边界吞噬**：正则提取期望值用排除字符类（[^\]\s]+ 而非 \S+），
  提取后先打印再对拍（] 被吃进期望值造成假 FAIL 的实录）
- **R32 新接口层命名对齐权威工具**：新接口层没有历史包袱，命名一次性对齐权威源
  （GNU_EH_FRAME 而非内部 EH_FRAME），交叉验证零映射成本

---

**统计**：32 条规则 ≈ 对应 30+ 次真实返工与踩坑；每条均可在每日日志（05_每日日志/）
中找到当时的执行证据与返工明细。规则库只增不删。

## R28 分诊工具崩溃路径可控律
任何对外暴露的 CLI 入口（尤其"给流水线/别的程序调用"的那种），失败路径必须**语义分层且零 traceback**：
- exit 2 = 分诊失败（格式不认识/文件读不了）——调用方应走"跳过或人工"分支
- exit 3 = 分诊通过但解析失败（截断/损坏）——调用方应走"样本损坏"分支，且知道**入口识别是对的**
- 一行 stderr 报告（`rekit: <file>: <中文原因>`），异常类型裸露给自动化脚本毫无意义
- 检查方法：负样本三件套（纯文本 / 魔数对但截断 / 半魔数），断言 exit 码 + stderr 无 "Traceback"

## R29 模板函数参数化保输出一致律
统一入口复用模块渲染时，不要"重写一份输出"，而是把模块 `main()` 参数化成 `main(argv=None)`
（None → `sys.argv[1:]`，否则用传入列表），入口用 `mod.main([path])` 调用：
- 直调行为零变化（回归零破坏）
- 输出逐字节一致是**构造性保证**，但仍要 diff 验证——因为它同时证明了"路由正确"
  （PE 样本经统一入口得到 PE 输出而非 ELF 崩溃，才是 diff 的真正证伪点）
